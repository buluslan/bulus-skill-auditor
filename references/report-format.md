# 报告格式（两段式产出：骨架脚本渲染 + 判断注入）

> 何时读：缝合最终报告时。原则：**骨架字段（表格/数字/聚合）由脚本渲染，重跑等价；判断内容（诊断叙述/建议）走注入位，随 json 留档**——两层不混写（开发哲学原则九）。

## 产物清单（一次审计最多产出四个文件）

| 文件 | 内容 | 生成方式 |
|---|---|---|
| `03-report.md` | 主报告（下述结构） | 骨架脚本渲染 + Agent 注入诊断段 |
| `Skill清单.md` | 清单模式产物：全量 skill 的分类+场景建议（轻量入口，日常翻） | 骨架渲染 + Agent 注入场景建议 |
| `01-metrics.json` / `02-eval-results.json` | 机器可复核数据（每条结论的数字都能指回这里） | 脚本 |

## 03-report.md 结构

```markdown
# Skill 审计报告 · <日期>

> 口径声明（固定段，数据诚实原则）：
> - token 为本地计量（o200k），与官方 tokenizer 偏差 ≤10%
> - 使用统计窗口：最近 <N> 天（<agent 各自声明；transcripts 默认保留 30 天）
> - 覆盖率：<如"已扫 87 个会话文件，跳过 3 个解析失败"；hermes 未装则声明跳过>
> - 本次审计花费：$<x>（未跑深度评测则写 ¥0）

## 一、总览（骨架）
- <N> 个 skill，分布：<claude-code 45 / codex 12 / …>
- 常驻总账：每次会话固定承载 <Σalways> token（≈<context 的 x%>）
- listing 预算状态：<健康 / 接近 / 超限（超限会静默截断，排在后面的 skill 从模型视野消失）>
- 30 天零激活：<n> 个

## 二、真账单（骨架，表格）
| skill | agent | 常驻token | 触发token | refs | 30天激活 | 最后使用 | 标记 |

## 三、诊断明细（骨架事实 + 注入判断）
### 重复（<n> 对，人工确认级）
### 疑似过时 / 模型已原生覆盖（仅当跑过 eval；否则此节写"未验证，跑深度评测可得"）
### 超重 / 结构问题
### 健康（一句带过数量即可，不展开）

## 四、高嫌疑名单（骨架，优先级排序）
| 优先级 | skill | 为什么上榜（信号） | 建议动作 |

## 五、处置建议（注入，按 refactor-playbook 的 R1-R6 格式逐条）
<!-- 每条含：信号 / 预计收益 / 风险前提 / [ ]建议人工确认 -->

## 六、深度评测结果（仅当跑了 eval；含 with/without 原始分与 Δ、成本）

## 七、附录：warnings / 复核命令表
<!-- 每个关键数字一行复核命令，如：o200k 重算 description 的单行 python -->
```

## 骨架/注入字段划分（硬约束）

- **骨架（脚本渲染，Agent 不得改）**：所有表格数字、聚合值、优先级分数、Δ 值、口径声明段
- **注入位（Agent 写）**：三节的判断叙述、五节全部、四节的"建议动作"列、清单的场景建议
- 注入内容同时存 `report-inject.json`（重跑骨架不丢判断层）

## 失配警示（机械化，完成≠合理原则）

脚本渲染时检查并**显性插入预警行**（不靠 Agent 注意力）：
- usage 覆盖异常（会话文件 < 阈值或 skip 环境变量检出）→ 顶部警示"使用数据不完整，'零激活'结论不可信"
- 扫描到 0 个 skill → 不出报告，直接报错（输入异常）
- listing 超限 → 总览加粗警示（这是静默截断风险，用户感知不到但伤害最大）

## Skill清单.md 结构（轻量产物）

```markdown
# 我的 Skill 清单 · <日期>（<N> 个）
> 用法：记不起装了什么时，把本文件丢给 Agent 让它自己判断该用哪个

## <分类：如 写作 / 电商 / 飞书 / 工程效率 / …>（分类由 Agent 注入）
- **<skill 名>**（<agent>，30天 <n> 次）：<一行干什么+什么时候用它>
```
